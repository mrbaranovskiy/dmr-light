# Validation record

Environment: AMD Ryzen 9 5900X, Windows build 22621, x64, .NET 8.0.31 runtime. Commands below reproduce the checks; timings are observations on this machine, not guarantees.

## Automated checks

```powershell
dotnet build Dmr.sln -c Release
dotnet run --project tests/Dmr.Tests -c Release
```

The test harness covers:

1. All input words and all one-bit corruptions for the seven ETSI small codes.
2. All three-bit corruptions of a representative Golay (20,8) word, all two-bit corruptions for every QR word, and extended-Hamming rejection.
3. The independent ETSI Annex D idle matrix, BPTC ordering, and single-bit correction.
4. RS generator-matrix values, single-byte correction, selected uncorrectable errors, and standard CRC known answers.
5. Voice LC masks and failure under the wrong message-type mask.
6. Embedded Full LC and common CACH Short LC assembly/coding.
7. Twenty-four AMBE payload vectors generated by a pinned, separately compiled upstream C decoder.
8. The middle 72-bit voice frame's split across the central signalling field.
9. Call identity isolation, session cleanup, privacy and opaque vendor handling.
10. Exact payloads and IDs for two simultaneous synthetic slots with different A-F phases.
11. Identical event streams for 1-, 137-, 4096-, and 16384-sample input chunks.
12. Inverted IQ and sync voice/data ambiguity resolution.
13. A 54,688 Hz input with 1 kHz residual offset, 80 ppm clock error, and added noise.
14. Late entry without headers.
15. Separate direct-mode slot-specific sync patterns.
16. MS streams retaining unknown absolute slot numbers.
17. Lost-burst erasures and subsequent recovery.
18. Exact frame recovery from 192 kHz IQ.
19. Two seconds of seeded noise without confirmed acquisitions or calls.
20. An adjacent DMR carrier 12.5 kHz away and 6 dB stronger in amplitude-derived power terms.
21. Raw signed-sample parsing, malformed pair rejection, and configuration checks.
22. Soft-symbol diagnostic cost ordering and original sample positions.
23. Sample discontinuity handling, EOF, and API lifecycle.
24. The supplied WAV's observed metadata and 216 opaque voice frames.
25. RFC 6229 ARC4 known answers at byte offsets 0, 256 and 4096.
26. Key file validation, key ownership and error-message disclosure checks.
27. 108 DMRA ARC4 frames from a separately compiled pinned C reference, including MI evolution and an all-zero key.
28. Valid PI acquisition and two slots with independent keys and message indicators.
29. Keystream advancement across missing B, F and A bursts and failed channel decoding.
30. Missing/wrong keys, absent PI headers and unsupported algorithm/vendor profiles.
31. Bad PI rejection, phase mismatch, re-acquisition and context reset on discontinuity.
32. Synthetic encrypted IQ through decrypted frames, identical output for two chunk sizes, and a JSONL output fixture.

All 32 groups pass. Privacy profile details and the remaining known-key radio validation gate are recorded in [PRIVACY.md](PRIVACY.md). ARC4 tests do not establish which privacy profile the supplied recording uses.

The synthetic RF generator uses the same RRC coefficient utility as the receiver, so it is not an independent RF oracle. Its burst and symbol streams have known expected content; the external recorded IQ and ETSI/C-decoder vectors provide independent checks at other boundaries. An independently labelled clean standard-FID radio capture remains an open validation gate.

```powershell
dotnet run --project src/Dmr.Cli -c Release -- dmr_test.wav --offset -12500 --output output/dmr_test.jsonl
```

Observed result: 72 voice bursts / 216 frames, 18 integrity-validated LC PDUs (five headers, twelve embedded LC messages, one terminator), colour code 15, FID 104 (`0x68`), MS sync, and one transmission. First voice burst is approximately 5.913 s and last approximately 10.173 s into the capture. The terminator appears at approximately 10.233 s. Absolute slot and standardized source/destination interpretation remain unknown.

Approximately 11.614 seconds of IQ decodes in roughly 0.5 seconds including JSONL writing on the listed machine. Run the command to measure the current build. The same voice payload sequence is visible using offset +12,500 Hz in this file; that observation is not treated as evidence of a second independent conversation.

## Synthetic noise characterization

```powershell
dotnet run --project tests/Dmr.Tests -c Release -- --benchmark output/characterization.json
```

Each point combines three deterministic captures, 432 expected frames in total. SNR is `10*log10(0.25/(2*sigma^2))` over the full 48 kHz complex input bandwidth. It is not Eb/N0, calibrated receiver sensitivity, or an ETSI conformance measure. The following baseline observations distinguish raw-frame errors from channel-corrected payload errors:

| Input SNR | Frames emitted | Exact raw 72-bit frames | Exact recovered 49-bit payloads |
|---|---:|---:|---:|
| No added noise | 432 | 432 | 432 |
| 23.01 dB | 432 | 432 | 432 |
| 16.99 dB | 432 | 432 | 432 |
| 10.97 dB | 432 | 432 | 432 |
| 7.45 dB | 432 | 432 | 432 |
| 4.95 dB | 432 | 426 | 428 |
| 1.43 dB | 432 | 257 | 328 |

This is a small empirical sweep with no statistical confidence interval. Successful protected-block decoding does not guarantee correct unprotected voice bits. In-memory synthetic replay was approximately 50 times real time; the JSONL/file path has different overhead.

## Remaining gates and roadmap status

- M0-M4 implementation exists and is exercised by the tests above. The independent clean over-air capture gate is still open, so this is a working receiver build rather than a certified or fully field-validated release.
- M5 has initial noise, drift, rate, adjacency, direct-mode, and failure-path coverage. Extensive fading/multipath, clipping, long-duration sampling drift, and false-acquisition measurements still need field characterization.
- M6 packet reassembly and Part 3 application decoding are not implemented. Data bursts are recognized and retained, and supported data headers are decoded.
- Live-device adapters, automatic channel discovery, vendor LC/privacy semantics, standalone reverse-channel semantics, and Tier III remain extensions.

The receiver intentionally leaves an unknown value unknown. Its output cannot prove that an arbitrary 72-bit frame is clear, playable, or correct.

The published Windows CLI was also run directly on the supplied recording. Its 395 JSONL events passed the Draft 2020-12 output schema. The generated `output/dmr_test.voice72.bin` contains 216 consecutive nine-byte received frames (1,944 bytes); its timing and metadata are in `output/dmr_test.jsonl`. Input and export hashes are recorded in `tests/fixtures/capture_manifest.json`.
